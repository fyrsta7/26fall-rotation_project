# 第六周自选方向拓展指南（软件优化智能体进阶）

本文档面向在第六周（机动拓展周）选择回到“方向一：软件优化智能体设计”开展深入探索的同学。第一周的必做实验已经在轻量基准 `PyOpt-Lite` 上验证了“热点剖析 + 调用链上下文 + 多轮执行反馈”的核心工作流；在第六周，你可以从以下三个研究级课题中任选其一推进，也可结合自己的观察提出新课题。

## 拓展方向一：面向真实大型仓库基准（GSO / SWE-fficiency）的长程优化智能体

### 研究问题

当待优化代码从单文件模块扩展到数万行规模的真实开源仓库（包含跨文件导入、复杂构建脚本与多层封装）时，单文件剖析容易受到初始化开销、跨语言扩展边界以及深层封装的干扰。本课题探索如何在有限的模型调用预算内设计仓库级责任定位机制，准确识别应当修改的文件与函数。

### 建议实施方案

1. **对接公开真实仓库基准**：选用 [GSO](https://github.com/gso-bench/gso)（NeurIPS 2025，102 道真实仓库任务）或 [SWE-fficiency](https://github.com/swefficiency/swefficiency)（ICML 2026）中的 5 至 10 道代表性任务（可优先从 `tornado`、`datasets`、`Pillow` 等构建流程轻便的仓库入手；如需使用课题组服务器预置的完整容器镜像与隔离评测环境，可直接联系方向负责人协助配置）。
2. **升级仓库级定位工具链**：在智能体中组合运行时调用栈采样与跨文件静态符号检索（例如定位高频跨文件调用边，区分“耗时载体函数”与“真正制造重复调用的上游决策函数”）。
3. **严格控制成本与评测协议**：限制每道题目的最大交互步数与验证次数，记录官方评测器输出的正确率、相对于原始版本的有效加速率以及达到人类专家提交性能水平的比例（`opt_commit`），并对典型成功与失败轨迹开展归因分析。

## 拓展方向二：结构化优化策略库与检索增强引导（SemOpt 进阶路线）

### 研究问题

动态剖析用于定位耗时集中的代码路径，而具体采用何种等价变换策略仍依赖领域经验。本课题研究如何从开源历史优化提交中提炼带有明确触发条件与安全边界的结构化策略库（Skill Library），引导大模型稳定生成语义等价的加速补丁。

### 建议实施方案

1. **复用公开历史优化知识库**：参考课题组往期公开仓库 [26spring-rotation_project](https://github.com/fyrsta7/26spring-rotation_project) 中的 100 个开源项目历史优化提交与聚类数据（对应论文 [SemOpt](https://arxiv.org/abs/2510.16384)），或从开源 Python 项目历史提交中整理 15 至 30 张结构化策略卡片。
2. **设计带安全边界的策略卡片格式**：每张策略卡片除给出变换意图外，显式写明**静态触发特征**（什么代码结构适用）与**负向禁用条件**（例如存在并发写入或外部可变引用时禁止消除拷贝、存在状态变更接口时必须配套添加缓存失效逻辑）。
3. **开展受控消融对比**：在统一测试集上对比“基础剖析反馈智能体”、“基于代码向量检索的少样本提示（RAG）”以及“两阶段策略卡片匹配智能体（先筛选策略卡片、再结合剖析证据生成补丁）”在测试通过率与几何平均加速比上的差异。

## 拓展方向三：跨任务经验积累与自进化优化智能体（RSI 探索路线）

### 研究问题

固定提示词与固定工具集的优化智能体在处理多道任务时，容易在不同题目上反复出现同类失误（例如缓存更新遗漏失效逻辑、引入额外中间容器开销或误改非热点辅助函数）。本课题探索设计元智能体（Meta-Agent），从开发集执行轨迹中自动诊断缺陷并改写优化智能体的提示词、检查清单或辅助工具，检验其在未见测试集上的泛化提升。

### 建议实施方案

1. **严格划分开发集与留出测试集**：例如将 `PyOpt-Lite` 的前 4 道任务（或自行扩充的开源优化任务）作为开发集（Dev），后 4 道任务作为留出测试集（Held-out Test）。元智能体在演化阶段**只允许读取开发集上的运行日志、测试报错与性能变化**，严禁读取测试集题目或参考补丁。
2. **实现轻量的“做题—反思—更新—验证”循环**：参考 [GEPA](https://arxiv.org/abs/2507.19457) 或 [Darwin Gödel Machine](https://arxiv.org/abs/2505.22954) 的思路，让元智能体对比开发集上的成功与失败案例，生成带具体适用条件的改进版系统提示词或新增静态检查函数，并在开发集上确认无退化后再保留新版本。
3. **独立检验泛化收益与过度泛化风险**：冻结演化后的智能体版本，在留出测试集上一次性评测演化前后的指标变化，分析学到的经验在哪些新任务上真正生效、在哪些任务上可能出现机械套用。
