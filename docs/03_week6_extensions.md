# 第六周自选方向拓展指南（软件优化智能体进阶）

本文档面向在第六周（机动拓展周）选择回到“方向一：软件优化智能体设计”开展深入探索的同学。以下三个进阶课题所需的评测集与代码均可直接从 GitHub 或 Hugging Face 公开仓库自行下载运行，无需额外申请内部数据。

## 拓展方向一：在公开仓库级基准（GSO / SWE-Perf）上探索跨文件定位与优化

### 研究问题

当待优化对象从单文件模块扩展到数万行规模的真实开源仓库时，单文件剖析容易受到初始化开销、多层模块封装与跨文件调用链的干扰。本课题探索如何在有限的模型调用预算内，为编程智能体设计轻量的跨文件热点定位与局部上下文筛选机制。

### 公开数据源与实施建议

1. 公开基准获取：直接从 Hugging Face 或 GitHub 获取公开基准 [GSO](https://huggingface.co/datasets/gso-bench/gso)（[官方评测库](https://github.com/gso-bench/gso)）或 [SWE-Perf](https://github.com/SWE-Perf/SWE-Perf)（[Hugging Face 数据集](https://huggingface.co/datasets/SWE-Perf/SWE-Perf)）。为降低本地构建开销，建议从纯 Python 或轻量依赖的仓库任务中挑选 5 至 10 道题目（例如 `tornado`、`datasets` 等仓库，可在本地虚拟环境中直接检出对应公开提交运行测试与性能脚本）。
2. 定位与优化流程设计：在 Codex CLI 或自定义脚本中组合动态调用栈剖析与跨文件符号检索，让智能体先输出候选修改文件与上游调用链证据，再生成补丁并运行目标仓库自带测试。
3. 评测与误差归因：统计测试通过率与相对于原始提交的实测加速比，对比“直接让智能体自由搜索整个仓库”与“先执行结构化剖析定位再修改代码”在成功率与 Token 消耗上的差异。

## 拓展方向二：基于公开效率数据集（PIE / EffiBench-X）的检索增强与技能归纳

### 研究问题

动态剖析能够指出耗时集中的代码区域，但模型未必熟悉特定语言或算法场景下的高效等价改写模式。本课题基于公开的成对代码效率数据集，对比示例检索增强（RAG）与结构化优化技能（Skill）归纳两种知识利用方式的效果。

### 公开数据源与实施建议

1. 公开数据集获取：选用 [PIE 公开数据集](https://github.com/madaan/pie-perf)（ICLR 2024，提供公开的 Python 与 C++“慢速提交—快速提交”程序对及测试用例）或 [EffiBench-X](https://huggingface.co/datasets/EffiBench/effibench-x)（[官方仓库](https://github.com/EffiBench/EffiBench-X)，包含 Python、C++、Java 等多语言效率评测题与基准测试脚本）。
2. 构建检索与技能模块：从 PIE 公开训练划分中抽取一批慢速与快速代码对，分别实现两种引导方式：一是按代码向量相似度检索最相近的 2 至 3 个示例放入提示词（RAG）；二是用大模型将训练样本归纳为十余条简短的优化技能卡片（写明适用特征、改写方法与易错边界），优化时先匹配技能卡片再修改代码。
3. 定量对比分析：在 PIE 公开测试子集或 EffiBench-X 的 20 至 30 道题目上，统一比较单轮直接优化、RAG 检索提示与技能卡片引导在功能通过率与平均加速比上的表现。

## 拓展方向三：基于公开任务集的自进化代码优化智能体（RSI 探索路线）

### 研究问题

固定提示词与固定检查步骤的优化智能体在处理一批任务时，容易在不同题目上重复出现同类失误（例如引入缓存却遗漏状态变更失效、优化了低频分支或破坏边界条件）。本课题探索设计轻量的元智能体（Meta-Agent），从开发集轨迹中自动诊断失败原因并改进智能体提示词或辅助检查工具。

### 公开数据源与实施建议

1. 数据划分与隔离：可将本仓库自带的 `PyOpt-Lite`（8 道题）与从 [EffiBench-X](https://huggingface.co/datasets/EffiBench/effibench-x) 或 [COFFE](https://github.com/JohnnyPeng18/Coffe) 中选取的 12 至 16 道公开 Python 效率题组合，严格切分为开发集（Dev）与留出测试集（Held-out Test）。演化阶段只允许读取开发集上的运行日志、测试报错与耗时变化，不得接触留出测试集。
2. 实现反思与更新循环：参考 [GEPA](https://github.com/gepa-ai/gepa)（`arXiv:2507.19457`）或 [Darwin Gödel Machine](https://arxiv.org/abs/2505.22954) 的思路，让元智能体读取优化智能体在开发集上的失败与低效轨迹，自动提炼带明确适用条件的改进版提示词或静态检查脚本，并在开发集复测无退化后保留新版本。
3. 留出集泛化验证：冻结演化前后的两个智能体版本，在留出测试集上一次性对比通过率与几何平均加速比，分析自动归纳的经验在哪些新任务上真正生效、在哪些场景下存在机械套用风险。
