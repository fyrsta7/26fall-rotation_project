# 软件性能优化领域发展脉络与论文阅读指南

本文档梳理自动代码性能优化技术从传统编译器规则到长程自进化智能体的四个演进阶段，并给出第一周（阅读 1 至 2 篇代表性论文）的具体选读建议，帮助同学们建立清晰的领域坐标系。

## 一、四个演进阶段总览

自动软件性能优化的核心演进线索，体现为**优化粒度从局部语法片段扩展到跨函数真实仓库**，同时**决策机制从静态手工规则演进到基于执行反馈与经验自演化的智能体系统**。

| 演进阶段 | 优化对象与粒度 | 核心技术机制 | 重点突破的瓶颈 | 阶段亮点代表作 |
| --- | --- | --- | --- | --- |
| **阶段一：传统规则与专用小型模型**（2022 及以前） | 编译器中间表示（IR）或局部函数片段 | 手工编写变换规则、遗传改进搜索、序列到序列专用微调模型 | 自动化局部低层指令与固定模式变换 | DeepDev-PERF (FSE 2022)、Supersonic (TSE 2024) |
| **阶段二：单函数与竞赛题大模型搜索**（2023–2024） | 算法竞赛提交或独立单函数（百行以内） | 少样本检索提示、运行时性能反馈、进化搜索算子 | 摆脱跨语言手工规则限制，引入执行耗时反馈指导迭代 | **SBLLM** (arXiv 2024 / ICSE 2025)、PIE (ICLR 2024)、EffiLearner (NeurIPS 2024) |
| **阶段三：真实仓库知识引导与跨函数智能体**（2025–2026） | 真实开源软件仓库（多文件、跨调用链） | 历史提交策略聚类（Skill/RAG）、动态剖析与静态调用链联合定位、协同补丁编辑 | 解决真实工程上下文缺失、局部热点与修改根因错位问题 | **SemOpt** (TOSEM 2026)、**PEACE** (ASE 2025)、**GSO** (NeurIPS 2025) |
| **阶段四：长程任务探索与自进化智能体**（2025–2026 前沿） | 复杂仓库长程优化任务与智能体框架自身 | 多步探测与验证循环、递归自我改进（RSI）、智能体运行框架（Harness）演化 | 让系统从历史成败轨迹中积累可迁移经验并自主改进工具与控制流 | **GEPA** (2025)、**Darwin Gödel Machine** (2025)、**Hyperagents** (2026) |

## 二、各阶段关键思路与演进动因

### 1. 传统规则、启发式搜索与早期深度学习（2022 及以前）

早期的自动性能优化主要依托编译器后端变换（如循环展开、常量传播、自动向量化）、运行时备忘录化（Memoization）以及基于遗传编程的程序改进（Genetic Improvement）。这类方法在底层指令与数值循环上具有严格的可证明安全性，但每类变换规则都需要领域专家逐条编码，难以理解高层业务数据结构语义，跨语言复用成本较高。

随后出现的专用深度学习方法尝试从开源历史提交中直接学习代码编辑映射。例如 [DeepDev-PERF](https://dl.acm.org/doi/10.1145/3540250.3549096)（FSE 2022）针对真实 C# 项目的性能提交微调预训练模型，[Supersonic](https://doi.org/10.1109/TSE.2024.3423769)（TSE 2024）利用序列到序列模型生成 C/C++ 小幅编辑补丁。受限于当时的模型参数规模与上下文窗口，这类专用模型只能处理高度局部的模式替换。

### 2. 单函数与竞赛题上的大模型提示、反馈与搜索（2023–2024）

通用大语言模型展现出丰富的跨语言算法与标准库知识后，研究者首先在结构清晰、测试完备的算法竞赛题与独立函数上探索优化方法。[PIE](https://arxiv.org/abs/2302.07867)（ICLR 2024）从竞赛提交历史中构建了“慢速实现—快速实现”等价程序对基准；[RAPGen](https://arxiv.org/abs/2306.17077)（2023）证明检索相似历史性能修复案例进行零样本或少样本提示，效果即可超越微调小型模型；[EffiLearner](https://proceedings.neurips.cc/paper_files/paper/2024/hash/99c66755871ae101a4cef87c67fb29e8-Abstract-Conference.html)（NeurIPS 2024）进一步将行级剖析开销反馈给大模型开展自优化。

这一阶段的代表性工作是 **[SBLLM](https://arxiv.org/abs/2408.12159)**（*Search-Based LLMs for Code Optimization*，2024 年公开预印本，发表于 ICSE 2025）。SBLLM 将大模型代码优化建模为迭代进化搜索过程：系统先从知识库中检索代表性优化模式启发初始候选种群，再根据单元测试与真实运行耗时淘汰劣质候选，并通过大模型驱动的交叉与变异提示算子持续组合不同优化思路。SBLLM 清晰展示了“模式检索 + 执行反馈 + 迭代搜索”相对于单轮提示的优势，但其实验对象仍集中于百行以内的独立竞赛程序。

### 3. 真实开源仓库中的知识引导与跨函数优化智能体（2025–2026）

进入真实大型软件仓库后，单函数竞赛题上的方法随即面临两项工程挑战：一是真实工程包含自定义抽象、隐式状态不变量与复杂构建环境；二是**性能剖析看到的热点函数未必是最佳修改位置**，大量冗余开销实际上来自上游调用循环、重复对象拷贝或跨文件接口契约。

围绕真实仓库场景，2025 至 2026 年涌现出三类关键进展：

- **仓库级评测基准**：**[GSO](https://arxiv.org/abs/2505.23671)**（NeurIPS 2025）从 NumPy、Pandas、Pillow、Tornado 等 10 个高性能代码库中构建了 102 个带真实性能工作负载的优化任务，要求智能体达到人类专家优化提交的性能水平；**[SWE-fficiency](https://arxiv.org/abs/2511.06090)**（ICML 2026）与 **[SWE-Perf](https://arxiv.org/abs/2507.12415)**（ICML 2026）进一步扩展了真实仓库工作负载评测规模。实验表明，直接套用通用代码修复智能体在真实性能优化上的成功率远低于功能缺陷修复。
- **规则与策略库引导**：课题组工作 **[SemOpt](https://arxiv.org/abs/2510.16384)**（ACM TOSEM 2026）从 100 个开源项目的历史提交中筛选并聚类提炼出可复用的结构化优化策略库，将项目热点分析与显式策略匹配相结合，解决了直接提示方向发散以及朴素文本检索（RAG，Retrieval-Augmented Generation）容易匹配表面语法相似却优化策略无关案例的问题。
- **跨函数协同编辑与定位**：**[PEACE](https://arxiv.org/abs/2510.17142)**（ASE 2025）面向真实 Python 仓库提出项目级效率优化框架，通过构造依赖感知的待优化函数序列并识别必须同步修改的关联位置，实现了跨多个函数的协同加速编辑；[POLO](https://www.ijcai.org/proceedings/2025/814)（IJCAI 2025）与 [Optimo](https://arxiv.org/abs/2607.23665)（2026）也分别从调用图成本传播与多粒度差分剖析角度改进了定位与优化精度。

### 4. 长程任务探索与自进化优化智能体（2025–2026 前沿）

在复杂软件仓库中实施可靠的性能优化是一项典型的**长程任务（Long-Horizon Task）**：智能体需要自主规划“运行基准负载 → 采集剖析热点 → 追踪上下游调用链 → 提出假设并修改代码 → 运行回归测试与性能复测 → 分析负优化或测试报错原因并回退修正”的完整研究循环。与此同时，研究者发现固定不变的智能体运行框架（Harness）在跨项目运行时会反复踩入相似陷阱（例如添加缓存却遗漏状态更新时的缓存失效、误将底层被调函数当作唯一修改点等）。

为此，最新前沿开始探索**递归自我改进（RSI，Recursive Self-Improvement）**与 **Harness 自演化**：在保持底层大模型参数冻结的条件下，引入元智能体（Meta-Agent）审视优化智能体在开发任务上的完整执行轨迹，诊断失败根因并自动演化提示词、结构化经验库、专用诊断工具乃至智能体自身的控制代码。代表性工作包括：

- **[GEPA](https://arxiv.org/abs/2507.19457)**（2025）：通过读取执行轨迹进行结构化语言反思与帕累托候选保留，在不训练模型权重的情况下迭代演化多模块智能体提示词。
- **[Darwin Gödel Machine (DGM)](https://arxiv.org/abs/2505.22954)**（2025）：维护一个编码智能体版本档案库，让基础模型根据基准评测日志直接修改智能体自身的工具与工作流代码，通过开放式演化持续提升软件工程表现。
- **[Hyperagents](https://arxiv.org/abs/2603.19461)**（2026）：将求解具体任务的任务智能体与负责改写系统的元智能体统一到同一套可自修改程序结构中，研究跨领域经验积累与元层改进机制。

## 三、第一周阅读清单与工作量说明（对标每周 1–2 篇论文要求）

严格对齐课题组“每周阅读 1 至 2 篇论文或等量学习资料”的整体安排，第一周的阅读任务分为**本仓库入门文档**与**1 至 2 篇代表性论文**两部分（上文提及的其余文献仅作为发展背景索引，无需在第一周逐篇阅读）：

1. **基础入门资料（必读，合计约 30–40 分钟）**：
   - 本仓库 `docs/01_api_and_agent_guide.md`（理解裸 API Key 与 Agent 外壳的区别及安装配置方法）与本文档前两节的发展脉络概览。
2. **代表性论文精读（合计阅读 1 至 2 篇，预计 3–4 小时）**：
   - **第 1 篇（经典方法建立直觉，二选一精读）**：
     - **[SBLLM](https://arxiv.org/abs/2408.12159)**（ICSE 2025）：面向单函数算法题的“模式检索 + 运行时耗时反馈 + 进化搜索”代表作，结构清晰，适合零基础快速理解大模型迭代优化的完整流程；
     - **[SemOpt](https://arxiv.org/abs/2510.16384)**（ACM TOSEM 2026，课题组论文）：理解如何从真实开源项目的历史提交中聚类提炼优化规则库，并结合热点分析引导大模型实施可靠优化。
   - **第 2 篇（近年真实仓库智能体新进展，二选一阅读，可重点阅读问题定义、方法设计与实验结论）**：
     - **[GSO](https://arxiv.org/abs/2505.23671)**（NeurIPS 2025）：了解真实开源软件仓库的性能优化基准如何构建、编程智能体在真实仓库上遇到了哪些核心瓶颈；
     - **[PEACE](https://arxiv.org/abs/2510.17142)**（ASE 2025）：了解从单函数走向项目级跨函数优化时，如何分析函数调用依赖并实施多位置协同编辑。
3. **第六周拓展选读（第一周不做要求）**：
   - 若计划在第六周选择本方向探索自进化代码优化智能体，届时可进一步阅读 **[GEPA](https://arxiv.org/abs/2507.19457)**、**[Darwin Gödel Machine](https://arxiv.org/abs/2505.22954)** 或 **[Hyperagents](https://arxiv.org/abs/2603.19461)**。
