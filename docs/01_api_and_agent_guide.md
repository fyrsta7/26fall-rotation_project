## 三、五分钟验证接口与最小智能体循环

主流模型服务大多兼容 OpenAI Python SDK 协议，切换服务商时仅需调整 `BASE_URL`、`API_KEY` 与 `MODEL` 三个配置项。

1. 安装依赖并复制本地配置文件：

   ```bash
   pip install -r requirements.txt
   cp config_template.py config.py
   ```

2. 编辑 `config.py`（该文件已列入 `.gitignore`，不会被 Git 提交），填入你的密钥、服务地址与模型名称。
3. 运行基础调用与缓存命中统计示例：

   ```bash
   python3 part1_basics/01_hello_api.py
   ```

   在代码生成与程序分析任务中，建议将采样温度 `temperature` 设为 `0.0` 至 `0.2`，以降低输出随机性。多轮交互时保持系统提示词（`system`）与前序上下文稳定，模型服务端会自动命中前缀键值缓存（KV Cache），显著减少输入计费与响应延迟。
4. 运行最小工具调用智能体示例：

   ```bash
   python3 part1_basics/02_structured_and_tools.py
   ```

   该脚本通过不到 100 行代码展示了智能体的标准工作循环：模型先调用 `get_hotspot_profile` 获取性能剖析热点，再按需调用 `read_source_file` 读取关联模块源码，最后结合两项观测结果给出跨函数优化方案。

## 四、面向代码优化的提示工程与智能体使用要点

无论在 Python 脚本中构造提示词（Prompt），还是在 Qoder、WorkBuddy 中驱动编程智能体完成代码加速，建议遵循以下三项设计原则：

1. **明确声明语义等价与边界约束**：性能优化的前提是不破坏原有功能契约。提示词需要明确要求保留公开类与函数的签名、返回值结构、异常类型以及状态变更时的缓存失效逻辑，并在每次生成补丁后运行单元测试加以验证。
2. **向模型提供动态性能剖析证据**：在包含十余个辅助函数的模块中，仅阅读静态源码容易误改只执行一次的初始化或格式化逻辑。先运行性能剖析工具（如 Python 标准库 `cProfile`）采集各函数的调用次数、自身耗时（`self_time`）与累计耗时（`cumulative_time`），再将热点排行输入模型，能够大幅提升瓶颈定位准确度。
3. **联合检视上下游调用链上下文**：底层叶子函数耗时占比突出，往往源于上游调用方（Caller）在循环内部重复解析参数、重复构造对象或未复用中间结果。将“上游调用方 — 热点函数 — 下游被调函数”的调用关系一并提供给智能体，要求其先输出简短的瓶颈归因再生成完整代码，有助于发现加速收益显著的跨函数协同修改方案。
